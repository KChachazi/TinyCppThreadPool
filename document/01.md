# 01. 线程生命周期：从创建到收尾

这篇笔记记录线程基础里最先需要搞清楚的两件事：线程和并发到底是什么，以及 C++ 的 `std::thread` 应该怎样正确收尾。

## 1. 先把概念理顺

### 1.1 进程与线程

一开始最容易混淆的，就是进程和线程。

- 进程可以理解为资源分配的基本单位。
- 线程可以理解为程序执行的基本单位。
- 同一个进程里的多个线程会共享地址空间和进程资源，但它们各自还有独立的执行栈和调度上下文。

这意味着：线程之间“共享得多”，所以并发问题也更容易出现。

### 1.2 并发与并行

把并发和并行分开以后，很多现象就能解释通了。

- 并发：同一时间段内处理多个任务。
- 并行：同一时刻真正同时执行多个任务，通常依赖多核 CPU。

初学阶段特别容易把“线程切换很快”误认为“线程一定是并行的”，但其实它们不是一回事。

### 1.3 主线程与子线程

程序启动后，通常先进入主线程。主线程可以再创建多个子线程去做别的任务。

主线程是否等待子线程结束，直接决定了整个程序的生命周期管理方式。

### 1.4 线程对象与真实线程

在 C++ 里，`std::thread` 是“线程对象”，它负责管理一个真实线程。

很多人刚开始也容易误解，以为 `std::thread` 就等于线程本身。实际上更准确的理解是：

- `std::thread` 是管理句柄。
- 真正执行任务的是底层线程。

### 1.5 `joinable()` 状态

`joinable()` 是用来判断线程对象还能不能被 `join()` 或 `detach()` 的接口。

一般来说，这几种情况都会让线程对象不再是 `joinable`：

- 默认构造的线程对象。
- 已经 `join()` 过的线程对象。
- 已经 `detach()` 过的线程对象。

## 2. 常用接口与基本写法

### 2.1 创建线程

```cpp
#include <thread>

void worker(int index) {
    // do work
}

int main() {
    std::thread t(worker, 1);
    t.join();
}
```

`std::thread` 构造时会接收一个可调用对象和它的参数。这个可调用对象既可以是普通函数，也可以是函数对象或者 lambda。

### 2.2 等待线程结束：`join()`

```cpp
std::thread t(worker, 1);
t.join();
```

`join()` 会阻塞当前线程，直到目标线程执行结束。

可以把它理解成：主线程先停下来，等子线程把活干完再继续。

### 2.3 分离线程：`detach()`

```cpp
std::thread t(worker, 1);
t.detach();
```

`detach()` 会把线程和 `std::thread` 对象分离。

分离之后，线程会继续独立运行，但线程对象不再负责等待它结束。这个接口在入门阶段一般先少用，等生命周期理解透了再说。

### 2.4 检查线程状态：`joinable()`

```cpp
if (t.joinable()) {
    t.join();
}
```

`joinable()` 很适合做安全判断，避免对无效线程对象重复 `join()` 或 `detach()`。

### 2.5 获取线程 ID

```cpp
std::cout << std::this_thread::get_id() << std::endl;
```

`std::this_thread::get_id()` 返回当前线程的 ID。

线程 ID 更适合用于调试和观察线程行为，而不是当成普通整数去处理。

### 2.6 线程休眠

```cpp
#include <chrono>
#include <thread>

std::this_thread::sleep_for(std::chrono::seconds(1));
```

`sleep_for` 可以让线程暂停一段时间。示例程序里常用它来观察线程调度顺序和生命周期变化。

## 3. 生命周期管理里的几个注意点

### 3.1 线程对象析构前必须处理完毕

如果 `std::thread` 对象在仍然 `joinable()` 时被析构，程序会调用 `std::terminate()`。

线程管理不能只停留在“创建成功”，更重要的是“结束时必须善后”。

### 3.2 主线程不能过早退出

如果主线程提前结束，整个进程可能直接退出，子线程也会被一起终止。

所以在入门阶段，通常会优先使用 `join()`，让主线程明确等子线程执行完。

### 3.3 输出交错是正常现象

多线程同时输出时，日志顺序可能交错。

这可以理解成并发执行的自然现象，而不是程序一定有错。后面如果想让输出更整齐，就得引入互斥保护。

### 3.4 打印方式要选对

线程 ID 这类对象更适合用 `std::cout` 直接输出。

像 `%d` 这种格式化占位符，并不适合直接打印 `std::thread::id`。

### 3.5 初学阶段优先用 `join()`

`detach()` 会让线程生命周期脱离管理，理解成本会明显上升。

所以在还没有把资源管理彻底理顺之前，通常会优先用 `join()`。

## 4. 这一阶段已经掌握的能力

1. 能创建多个 `std::thread`。
2. 能让工作线程执行一个独立函数。
3. 能用 `join()` 等待线程结束。
4. 能用 `joinable()` 观察线程对象状态变化。
5. 能通过 `std::this_thread::get_id()` 区分主线程和子线程。
6. 能解释为什么线程对象不能在仍可连接时直接析构。

## 5. 小结

到目前为止，线程的理解已经从“会创建”推进到了“会收尾”。

现在至少可以说清楚：线程是什么、怎么创建、怎么等待、为什么要管理生命周期，以及为什么多线程输出会交错。
