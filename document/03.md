# 03. 锁的工程化使用与死锁规避

前面把数据竞争和互斥保护练过以后，下一步自然就会碰到一个更实际的问题：

不是“有没有加锁”，而是“加锁之后安不安全”。

这节我主要想把死锁这件事讲清楚，然后再看怎么把它修掉。

## 1. 本节目标

1. 明白为什么“加了锁”不等于“加得安全”。
2. 能描述死锁是怎么形成等待链条的。
3. 熟悉 `lock_guard`、`unique_lock`、`scoped_lock` 的常见使用场景。
4. 能用一致加锁顺序或者 `scoped_lock` 避免死锁。

## 2. 核心概念

### 2.1 死锁

死锁就是两个或多个线程互相等待对方释放锁，最后谁也走不下去。

这类问题最常见的来源，不是单把锁本身，而是多把锁交错使用的时候。

### 2.2 高风险模式

最典型的危险场景就是：

- 线程 A 先拿 `m1` 再拿 `m2`。
- 线程 B 先拿 `m2` 再拿 `m1`。

只要时机撞上，就很容易卡住。

### 2.3 工程化加锁

我现在更倾向于把锁看成“资源边界”，而不是“我只是加一下试试”。

所以这节里会优先用 RAII 风格的锁：

- `std::lock_guard`
- `std::unique_lock`
- `std::scoped_lock`

这样做的好处很直接：不容易忘记解锁。

## 3. 常用接口和典型用法

### 3.1 `lock_guard`

适合单把锁、短临界区。

它的特点很简单：进入作用域时加锁，离开作用域时自动解锁。

### 3.2 `unique_lock`

适合需要更灵活控制锁生命周期的场景。

比如延迟加锁、提前解锁，或者和条件变量配合时，都会更常见。

### 3.3 `scoped_lock`

适合多把锁一起拿下来的场景。

它比较适合用来规避死锁，因为它会把多把互斥量作为一个整体来处理。

## 4. 本轮实现需求

我这轮实现分成两段：

### 4.1 Deadlock Demo

构造两把锁 `m1` 和 `m2`，两个线程以相反顺序加锁，加入短暂休眠并打印动作日志，尽量把死锁现象演出来。

### 4.2 Fixed Demo

把死锁修掉，方式可以二选一，也可以都做：

- 保持一致加锁顺序。
- 使用 `scoped_lock` 同时锁两把锁。

## 5. 实现示例

### 5.1 死锁复现

```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::mutex mtx1, mtx2;

void func1() {
    printf("Thread 1 is trying to acquire locks...\n");
    std::lock_guard<std::mutex> lock1(mtx1);
    std::this_thread::sleep_for(std::chrono::milliseconds(100));
    std::lock_guard<std::mutex> lock2(mtx2);
    std::cout << "Thread 1 acquired both locks" << std::endl;
}

void func2() {
    printf("Thread 2 is trying to acquire locks...\n");
    std::lock_guard<std::mutex> lock2(mtx2);
    std::this_thread::sleep_for(std::chrono::milliseconds(100));
    std::lock_guard<std::mutex> lock1(mtx1);
    std::cout << "Thread 2 acquired both locks" << std::endl;
}

int main() {
    std::thread t1(func1);
    std::thread t2(func2);
    t1.join();
    t2.join();
    return 0;
}
```

### 5.2 修复方式

```cpp
void worker(const char* name) {
    std::cout << name << " is trying to acquire mtx1 + mtx2" << std::endl;

    std::scoped_lock lock(mtx1, mtx2);

    std::cout << name << " acquired both locks" << std::endl;
    std::this_thread::sleep_for(std::chrono::milliseconds(50));
    ++shared_value;
    std::cout << name << " updated shared_value to " << shared_value << std::endl;
}
```

这个写法的关键点是：两把锁一起拿，避免了两条线程走向相反顺序时互相卡住。

## 7. 代码约束

1. 必须使用 `std::thread`。
2. 必须保持 RAII 风格加锁，不建议全程手写 `lock()` / `unlock()`。
3. 本节不引入条件变量。
4. 本节不写线程池实现。
