# 03. 第4节：锁的工程化使用与死锁规避

## 本节目标
- 理解为什么会加锁不等于加得安全。
- 能描述死锁形成的等待链条。
- 掌握 lock_guard、unique_lock、scoped_lock 的常见场景。
- 能用一致加锁顺序或 scoped_lock 避免死锁。

## 关键概念
- 死锁：两个或多个线程互相等待对方释放锁，最终都无法继续。
- 高风险模式：线程A先拿 m1 再拿 m2；线程B先拿 m2 再拿 m1。
- 工程化加锁：优先用 RAII（lock_guard、unique_lock、scoped_lock），减少忘记解锁的风险。

## 常用接口和典型用法
- lock_guard
  适合单锁、短临界区，进入作用域加锁，退出作用域自动解锁。
- unique_lock
  适合需要更灵活控制锁生命周期的场景，可延迟加锁或手动解锁。
- scoped_lock
  适合多锁场景，可一次性安全地锁住多把互斥量，用于规避死锁。

## 实现
死锁复现：
```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::mutex mtx1, mtx2;

void func1() {
    printf("Thread 1 is trying to acquire locks...\n");
    std::lock_guard<std::mutex> lock1(mtx1);
    std::this_thread::sleep_for(std::chrono::milliseconds(100)); // 模拟工作
    std::lock_guard<std::mutex> lock2(mtx2);
    std::cout << "Thread 1 acquired both locks" << std::endl;
}

void func2() {
    printf("Thread 2 is trying to acquire locks...\n");
    std::lock_guard<std::mutex> lock2(mtx2);
    std::this_thread::sleep_for(std::chrono::milliseconds(100)); // 模拟工作
    std::lock_guard<std::mutex> lock1(mtx1);
    std::cout << "Thread 2 acquired both locks" << std::endl;
}

// 死锁复现
int main() {
    std::thread t1(func1);
    std::thread t2(func2);
    t1.join();
    t2.join();
    return 0;
}
```
